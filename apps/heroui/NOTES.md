## Setup steps and files

1. Copied `apps/baseline` without `node_modules`, `ios`, `android` or `.expo`, and deleted the copied `package-lock.json`.
2. `package.json`: name changed to `am-ui-lab-heroui`. Added the packages in the table above with `npm install heroui-native@1.0.11 uniwind@1.13.0 tailwindcss@4.3.3 tailwind-variants@3.3.1 tailwind-merge@3.7.0 react-native-svg@15.15.4`.
3. `app.json`: name `UI Lab HeroUI`, slug `am-ui-lab-heroui`, scheme `amuilab-heroui`, `ios.bundleIdentifier` and `android.package` both set to `dev.asimmalik.uilab.heroui`.
4. `metro.config.js`: kept `watchFolders` for `../../shared`, then wrapped the config in `withUniwindConfig(config, { cssEntryFile: './src/global.css', dtsFile: './src/uniwind-types.d.ts', extraThemes: ['brand'] })`. Uniwind says it must be the outermost wrapper. HeroUI's theming page also wraps with `wrapWithReanimatedMetroConfig`; the quick start doesn't, and neither does the baseline, so it's left out.
5. `src/global.css`: `@import 'tailwindcss'; @import 'uniwind'; @import 'heroui-native/styles';`, followed by the token themes (see Theming). There's no `@source` line, because the quick start says it isn't needed from 1.0.8.
6. `src/uniwind-types.d.ts`: generated by Uniwind the first time Metro runs (here, during `expo export`). It types `ThemeName` as `'light' | 'dark' | 'brand'`. It's generated, so don't edit it.
7. `src/css.d.ts`: `declare module '*.css';` (see Errors and fixes).
8. `src/app/_layout.tsx`: imports `../global.css`. The tree is `GestureHandlerRootView` > `HeroUINativeProvider` > `BottomSheetModalProvider` (needed only for the raw gorhom modal) > Stack. Calls `Uniwind.setTheme('light')` at module load so the app starts in the same theme as the baseline.
9. `tsconfig.json`: unchanged. It still has the `@shared/*` path.
10. No Babel config. Uniwind and HeroUI don't need one.

HeroUI is imported granularly everywhere (`heroui-native/button`, `heroui-native/provider` and so on), as the quick start recommends for bundle size. Importing from the package root would pull in the whole library.

## Theming

- **Tokens to CSS variables:** `src/global.css` overrides HeroUI's variables in `@layer theme { :root { @variant light | dark | brand { ... } } }`, which is the structure HeroUI's own `variables.css` uses. Every HeroUI variable is declared in all three themes, because Uniwind requires the same variable set in each theme.
- **Mapping:** background→`--background`; text→`--foreground`, `--*-foreground`; surface→`--surface`, `--default`, `--surface-secondary/tertiary`; surfaceRaised→`--overlay`, `--field-background`, `--segment`; textMuted→`--muted`, `--field-placeholder`; border→`--border`, `--separator`, `--field-border`; primary→`--accent`, `--link`; onPrimary→`--accent-foreground`; danger/onDanger→`--danger`/`--danger-foreground`; success→`--success`; focus→`--focus`; scrim→`--backdrop`.
- **Values the tokens don't cover:** `--success-foreground` uses white (light and brand) or the dark background colour (dark). `--warning` and `--warning-foreground` keep HeroUI's defaults. Shadows keep HeroUI's defaults.
- **`@theme` overrides:** `--radius: 10px` (radius.md), `--field-radius: 10px`, and `--field-border-width: 1px`, because HeroUI's default of 0px would draw the text field with no border, unlike the baseline.
- **Spacing and type:** passed as RN `style` straight from `shared/tokens.ts`. Colours always come from theme classNames such as `text-foreground` and `bg-accent`, so they follow the active theme.
- **Runtime switch:** `Uniwind.setTheme(name)`. `useUniwind().theme` gives the current name. `brand` must be listed in `extraThemes` in the Metro config. There's no React theme context: Uniwind restyles subscribed components itself.
- **React Navigation header:** colours come from `useThemeColor(['surface', 'foreground', 'background'])`.

### Third-party @gorhom/bottom-sheet (item 13)

With no mapping argument, `withUniwind` maps every `*Style` prop to a `*ClassName` prop, both in its types (`ApplyUniwind`) and at runtime (`withAutoUniwind`). So:

```tsx
const StyledBottomSheetModal = withUniwind(BottomSheetModal);
const StyledBottomSheetView = withUniwind(BottomSheetView);

<StyledBottomSheetModal
  ref={sheetRef}
  backgroundClassName="bg-overlay"          // -> backgroundStyle
  handleIndicatorClassName="bg-border"      // -> handleIndicatorStyle
  backdropComponent={(p) => <BottomSheetBackdrop {...p} appearsOnIndex={0} disappearsOnIndex={-1} pressBehavior="close" />}>
  <StyledBottomSheetView testID="test-sheet-gorhom" style={{ padding: space.xl, gap: space.md }}>
    <Text className="text-overlay-foreground">…</Text>
```

The ref type has to be `BottomSheetModal<unknown>` (see Errors and fixes).

### @expo/ui BottomSheet

Added after the first round of tests, to check whether `@expo/ui`'s universal `BottomSheet` behaves the same outside the baseline. It is filled with `@expo/ui`'s own `Column`, `Text` and `Button`, as [Expo's docs](https://docs.expo.dev/versions/v57.0.0/sdk/ui/universal/bottomsheet/) show: React Native views inside it don't receive touches unless wrapped in `RNHostView`. The Close button carries `accessibilityIdentifier('test-sheet-expoui-close')` and the title `accessibilityAddTraits(['isHeader'])`, both from `@expo/ui/swift-ui/modifiers`.

**Result (2026-10-24, iPhone 17 Pro simulator, iOS 26.4, Release):** 5 / 5 sheet checks in `scripts/a11y-audit.mjs`, including the screen behind being hidden from VoiceOver. Opened by hand in the dark theme: the sheet showed the theme's surface and text colours.

`src/components/expo-sheet.tsx`. Colours come from HeroUI's `useThemeColor(['overlay', 'overlay-foreground', 'muted'])`, as for the Host, and are the same tokens as the gorhom sheet. Spacing and font sizes come from the shared `space` / `type` tokens, as in the gorhom sheet.

## Accessibility: what the library provides (from source, unverified)

- **Reduce Motion:** `GlobalAnimationSettingsProvider` disables all HeroUI animations when Reanimated's `useReducedMotion()` is true. The Reanimated docs and its types say that hook returns the value "when the app started", and changing the setting "doesn't cause your components to rerender". **Expect the at-launch check to pass and the switched-on-while-running check to fail.**
- **Dynamic Type:** `HeroText` sets `allowFontScaling` and no max multiplier by default. A few internal parts cap it: Avatar at 1.4 and InputOTP at 1.6, neither used here. The provider's `config.textProps` can set `maxFontSizeMultiplier`; left at the default.
- **VoiceOver containment:** the prop is `unstable_accessibilityContainerViewIsModal` (`@default false`, iOS only) on `Dialog.Portal`, `BottomSheet.Portal`, `Select.Portal`, `Popover`, `Menu` and the `ToastProvider` config. Left at the default, as instructed. Content also gets `role="dialog"` + `aria-modal` on Dialog, BottomSheet and Select.
- **Issue #372** ("BottomSheet.Portal FullWindowOverlay blocks the accessibility tree") is still **open** on GitHub. But in 1.0.11, `helpers/internal/components/full-window-overlay.tsx` already passes `unstable_accessibilityContainerViewIsModal = false` to react-native-screens by default, which is the fix the issue proposes. Whether the background stays reachable while a sheet is mounted or closed **needs measuring.**
- **Roles and state from primitives:** Button (`accessibilityRole="button"` with `accessibilityState.disabled`, no busy state); Switch and Checkbox (`role` with `aria-checked` and `accessibilityState`); RadioGroup (`radiogroup`, with `radio` and `aria-checked` per item); Select trigger (`role="combobox"`, but `aria-expanded` doesn't appear in the trigger source); Select items (`role="option"` with `aria-checked`); Tabs (`tablist`, `tab` with `aria-selected`, `tabpanel`); Dialog and BottomSheet titles (`role="heading"`, linked with `aria-labelledby`); Toast (`role="status"` with `aria-live="polite"`, which RN only honours on Android).
- **ControlField** (items 3 and 4): the root is a plain `Pressable` with no role, wrapping the inner `role="switch"` or `role="checkbox"` node. On iOS a focusable parent can swallow the child's role. **Needs measuring.**
- **TextField** doesn't link `Label` or `Description` to `Input` automatically.
- **No announcements:** `FieldError` has no live region and doesn't call `announceForAccessibility`. Toast relies on `aria-live`, so on iOS neither the error nor the toast should be announced. Nothing was added to compensate.

## Manual accessibility additions

| Where | Prop | Why |
| --- | --- | --- |
| Text field `Label.Text` / `Input` | `nativeID` + `aria-labelledby` | Per HeroUI's Label docs ("Used to link label to form fields via aria-labelledby"). RN only honours `aria-labelledby` on Android. |
| Text field `Description` / `Input` | `nativeID` + `aria-describedby` | Per HeroUI's Description docs. **RN 0.86 has no `aria-describedby` support** (no match anywhere in `react-native/Libraries`). TypeScript accepts it only because hyphenated JSX props aren't type-checked, so this is a no-op. |
| Radio group + theme switcher `RadioGroup` | `aria-label` | HeroUI has no group-label prop or Label linkage for RadioGroup. The spec requires a group label. |
| Screen title + section headings | `role="heading"` | On plain RN `Text`, as in the baseline. Not a HeroUI component. |

Not added (the baseline does these by hand): `aria-busy` on the loading button, `announceForAccessibility` for the email error and the toast, and `aria-invalid` on the input. Combined labels on list rows were also not added; `ListGroup.Item` defaults are left in place. The gorhom sheet title (item 13) has no `role="heading"`, because gorhom doesn't provide one.

## Errors and fixes

1. `tsc`: `TS2882: Cannot find module or type declarations for side-effect import of '../global.css'`. TypeScript 6 checks side-effect imports, and Uniwind's generated d.ts doesn't declare `*.css`. Fixed with `src/css.d.ts` (`declare module '*.css';`).
2. `tsc`: `Property 'testID' does not exist on type ... BottomSheetContentProps`. `BottomSheet.Content` takes gorhom `BottomSheetProps`, which has no testID. Fixed by moving the testID to an inner `View`.
3. `tsc`: `RefObject<BottomSheetModal | null>` isn't assignable to `ForwardedRef<BottomSheetModal<unknown>>`, because `withUniwind`'s `ComponentPropsWithRef` resolves the generic to `unknown`. Fixed by typing the ref as `BottomSheetModal<unknown>`.
4. Before the first Metro run, `Uniwind.setTheme('brand')` isn't constrained, because `ThemeName` falls back to `string`. Running `expo export` once generates `src/uniwind-types.d.ts`; after that, `tsc` is clean.

## What didn't work or isn't available

- No loading state on Button, and no busy state exposed.
- No indeterminate Checkbox.
- No form-field linking (label, description and error to input) beyond `nativeID` hints, and the `aria-describedby` pattern in the docs does nothing on RN.
- `BottomSheet.Content` can't take a testID.
- The Reduce Motion runtime toggle isn't followed (Reanimated `useReducedMotion` limitation). Unverified.

The lab moved from the iPhone 17 Pro simulator on iOS 26.4 to the iPhone 17 simulator on iOS 27.0 (Xcode 27.1). Expo SDK 57 apps built with the iOS 27 SDK need the UIKit scene life cycle, which SDK 57 adds as an opt-in:
