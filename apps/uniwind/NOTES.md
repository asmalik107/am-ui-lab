Built 2026-10-22. Nothing has run on a simulator or device yet; see "Unverified".

## Library and versions

| Package | Version | How installed |

## Setup steps and files touched

1. Copied `apps/baseline` without node_modules, ios, android or .expo. Ran `npm ci` (baseline lockfile), then installed the two packages above.
2. Renamed the app:
   - `package.json` name: `am-ui-lab-uniwind` (also in `package-lock.json`)
   - `app.json` name `UI Lab Uniwind`, slug `am-ui-lab-uniwind`, scheme `amuilab-uniwind`
   - iOS bundle identifier and Android package: `dev.asimmalik.uilab.uniwind`
3. **`metro.config.js`:** kept `watchFolders` for `../../shared`, then wrapped the config in `withUniwindConfig(config, { cssEntryFile: './src/global.css', dtsFile: './src/uniwind-types.d.ts', extraThemes: ['brand'] })`. Uniwind must be the outermost wrapper.
4. **`src/global.css` (new):** `@import 'tailwindcss'; @import 'uniwind';`, then the tokens (see Theming). It sits in `src/`, so Tailwind scans `src/` for class names; no `@source` line needed (all classNames live under `src/`).
5. **`src/uniwind-types.d.ts`:** generated by Uniwind on the first Metro run (here, `expo export`). Types the theme names as `'light' | 'dark' | 'brand'`. Don't edit it.
6. **`src/css.d.ts` (new):** `declare module '*.css';`, the same fix the heroui app needed for TypeScript 6's side-effect-import check.
7. **`src/app/_layout.tsx`:** imports `../global.css` (in a component file, not the entry, as the quickstart says). Calls `Uniwind.setTheme('light')` at module load: Uniwind defaults to adaptive themes that follow the device, and the baseline starts on light.
8. Deleted `src/theme.tsx`, the baseline's React-context provider. There is no provider.
9. Rewrote the styling in `src/app/_layout.tsx`, `src/app/index.tsx`, `src/app/list.tsx`, `src/components/controls.tsx` and `src/components/overlays.tsx`. Every `style` / `StyleSheet` / inline style became a `className`, except `GestureHandlerRootView style={{ flex: 1 }}` (not an RN component Uniwind patches). `src/a11y.ts` and `src/perf.tsx` are byte-identical to the baseline's.
10. Perf wiring copied from `apps/unistyles`: `<PerfReadout />` in the layout, `mark()` / `Uniwind.setTheme()` / `measure('theme')` in the theme switcher, `<PerfTouch onTouchStart={mark}>` (a `View`) around `<Link href="/list" asChild><Button …/></Link>`, and `onLayout={useListMeasure()}` on the FlatList.
11. `tsconfig.json`: unchanged (still has `@shared/*`). No Babel config: Uniwind doesn't need one.

## Errors hit and fixes

None at build time. Two things carried over from the heroui app's notes and applied up front:
- `src/css.d.ts` for `TS2882` on `import '../global.css'`.
- The gorhom ref is typed `BottomSheetModal<unknown>` (in `index.tsx` and `forwardRef` in `overlays.tsx`), because `withUniwind`'s prop types resolve gorhom's generic to `unknown`.

Order matters: `npx tsc --noEmit` should run after one Metro run (`expo export` or `expo start`), which generates `src/uniwind-types.d.ts`. Before that, `Uniwind.setTheme` accepts any string.

## Theming

- **Colours:** one `--color-*` variable per token in `@layer theme { :root { @variant light | dark | brand { … } } }`. Names are kebab-case versions of `shared/tokens.ts` (`surfaceRaised` to `--color-surface-raised`, `onPrimary` to `--color-on-primary`), so classes read `bg-surface-raised`, `text-text-muted`, `accent-primary`. Values were copied by hand. In the compiled bundle the `rgba()` scrims become 8-digit hex (`#00000080`), which RN accepts.
- **Spacing:** `--spacing: 4px` in `@theme`, so Tailwind's numeric scale maps exactly to the tokens: xs 4 = `1`, sm 8 = `2`, md 12 = `3`, lg 16 = `4`, xl 24 = `6`, xxl 32 = `8`. Set in px so it doesn't depend on the rem polyfill.
- **Radii:** `--radius-sm: 6px`, `--radius-md: 10px`, `--radius-lg: 16px` (overrides Tailwind's defaults); `rounded-full` for `radius.full`.
- **Type:** `--text-caption|body|label|title|heading` with `--text-*--line-height` (13/18, 16/22, 15/20, 20/26, 28/34). Weights are `font-semibold` (label) and `font-bold` (title, heading) on each element. I confirmed in the unminified bundle (`expo export --no-bytecode`) that `text-body` compiles to `fontSize` 16 + `lineHeight` 22.
- **Minimum targets:** `ios:min-h-11 android:min-h-12` (44 / 48), plus `min-w` on buttons. `min-h`, never `h`, so controls grow with the text.
- **Dynamic Type:** nothing disables font scaling. RN `Text` multiplies the className's `fontSize` by the system text size, as in the baseline. The checkbox box and radio ring are fixed sizes, as in the baseline (the Unistyles app scales them; this one doesn't).
- **Runtime switch:** `Uniwind.setTheme('light' | 'dark' | 'brand')`. No provider. Per the docs, setting `light` or `dark` also calls `Appearance.setColorScheme`, so the RN Modal and system UI follow it. `brand` is not light or dark, so the docs don't say what it sets there.
- **Class names:** always complete strings. Some are joined with template literals (for example `${targetH} flex-row …`), but every class is a full literal somewhere in the source, which is what Tailwind's scanner needs. I checked that each conditional class (`opacity-[0.45]`, `active:opacity-80`, `border-b-[3px]`, `size-[22px]`, `accent-*`, `ios:min-h-11`) is in the compiled stylesheet.

## How the third-party sheet and @expo/ui are themed

**@gorhom/bottom-sheet (item 13).** gorhom isn't one of the RN components Uniwind patches, and `backgroundStyle` / `handleIndicatorStyle` aren't `style`. `withUniwind` with no mapping gives every `*Style` prop a `*ClassName` twin, resolved against the active theme. This is the same approach as the heroui app.

```tsx
// src/components/overlays.tsx
const ThemedBottomSheetModal = withUniwind(BottomSheetModal);
const ThemedBottomSheetView = withUniwind(BottomSheetView);

<ThemedBottomSheetModal
  ref={ref}
  accessible={false}
  backgroundClassName="bg-surface-raised"   // -> backgroundStyle
  handleIndicatorClassName="bg-border"      // -> handleIndicatorStyle
  backdropComponent={(p) => <BottomSheetBackdrop {...p} appearsOnIndex={0} disappearsOnIndex={-1} pressBehavior="close" />}>
  <ThemedBottomSheetView testID={testID} aria-modal className="gap-3 p-6 pb-8">
```

**@expo/ui (item 14).** `Host` takes `colorScheme` and `seedColor` as props. The name comes from `useUniwind()`, and the colour from `useCSSVariable('--color-primary')`. That variable resolves because `bg-primary` / `text-primary` are used in classNames, which the docs require. The hook returns `string | number | undefined`, so the value is narrowed to a string.

```tsx
// src/app/index.tsx
function ThemedHost({ children }: { children: ReactNode }) {
  const { theme } = useUniwind();
  const primary = useCSSVariable('--color-primary');
  return (
    <Host matchContents colorScheme={theme === 'dark' ? 'dark' : 'light'} seedColor={typeof primary === 'string' ? primary : undefined}>
      {children}
    </Host>
  );
}
```

## @expo/ui BottomSheet

Added after the first round of tests, to check whether `@expo/ui`'s universal `BottomSheet` behaves the same outside the baseline. It is filled with `@expo/ui`'s own `Column`, `Text` and `Button`, as [Expo's docs](https://docs.expo.dev/versions/v57.0.0/sdk/ui/universal/bottomsheet/) show: React Native views inside it don't receive touches unless wrapped in `RNHostView`. The Close button carries `accessibilityIdentifier('test-sheet-expoui-close')` and the title `accessibilityAddTraits(['isHeader'])`, both from `@expo/ui/swift-ui/modifiers`.

**Result (2026-10-24, iPhone 17 Pro simulator, iOS 26.4, Release):** 5 / 5 sheet checks in `scripts/a11y-audit.mjs`, including the screen behind being hidden from VoiceOver. Opened by hand in the dark theme: the sheet showed the theme's surface and text colours.

`containerColor`, `textStyle` and `Column`'s `spacing` are plain props. The values come from `useCSSVariable`, as for the Host: `--color-surface-raised`, `--color-text`, `--color-text-muted`, `--text-title`, `--text-body` and `--spacing` (× 3 for `gap-3`, the gorhom sheet's gap). The hook returns `string | number | undefined`, so colours are narrowed to strings and sizes to numbers.

## Could not make work / deviations

- **Header title:** `'Uniwind'`, where the baseline has `'Baseline (React Native)'`. Intentional.
- **List link:** uses `<Link href="/list" asChild>` around the Button, inside the `PerfTouch` wrapper, copied from the Unistyles app. The baseline uses `router.push` in `onPress`.
- **`GestureHandlerRootView`** keeps `style={{ flex: 1 }}`. It isn't an RN core component, so a `className` there would need `withUniwind`, which isn't worth it for one static style.
- **Checkbox and radio glyph sizes** don't scale with the text size (same as the baseline). Uniwind's free tier has no font-scale value to put in a className.
- Nothing else was knowingly left out.
